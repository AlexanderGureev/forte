# Рекомендации по репозиторию

## Структура проекта и модулей

Клиентское приложение на Vite, React и TypeScript для справочника по фортепианной импровизации. Исходный код находится в `src/`: `src/music` - музыкальная теория, `src/state` - Zustand-состояние и селекторы, `src/scene` - React Three Fiber/Three.js, `src/ui` - HUD и примитивные компоненты, `src/styles` - общие CSS. Тесты лежат рядом с кодом в `__tests__`, например `src/music/__tests__`. `docs` и `spec` содержат документацию и заметки по реализации. Не редактируйте вручную сгенерированные `dist` и `coverage`.

## Команды сборки, тестов и разработки

Используйте npm; lock-файл проекта - `package-lock.json`.

- `npm install`: установить зависимости.
- `npm run dev`: запустить Vite dev server.
- `npm run build`: выполнить `tsc -b` и production-сборку Vite.
- `npm run preview`: локально открыть production-сборку.
- `npm run test`: один раз запустить набор тестов Vitest.
- `npm run test:coverage`: запустить Vitest с V8 coverage.
- `npm run typecheck`: проверить TypeScript-проекты без сборки ассетов.
- `npm run lint`: запустить ESLint по репозиторию.

## Стиль кода и именование

- Используйте TypeScript-модули и функциональные React-компоненты. Следуйте текущему стилю: два пробела, одинарные кавычки, точки с запятой, именованные экспорты, `PascalCase` для файлов компонентов (`ChordPanel.tsx`) и scoped CSS-классы (`primitive-mini-keyboard__key`).
- Доменные типы держите в `src/music/types.ts` или соседних доменных модулях.
- Правила музыкальной теории должны оставаться в `src/music` и derived state/view-model коде. UI и 3D-сцена рендерят готовые модели, не дублируя логику гамм, аккордов, прогрессий или знаков при ключе.
- Вносите минимальное корректное изменение. Не добавляйте helpers без второго места использования и абстракции "на всякий случай".
- Предпочитайте простые TypeScript-функции и `type` aliases классам или фреймворкоподобным абстракциям.
- Пишите линейный код сверху вниз: сначала валидируйте входные данные, используйте ранние `return`/`continue`, называйте намерение, а не механику.
- Держите одну концепцию на функцию: разделяйте validate, transform, fetch и mutate. У каждой ответственности должен быть один владелец.
- Используйте дискриминирующие поля (`mode`, `kind`, `status`) вместо связанных boolean-флагов.

## Правила тестирования

Тесты используют Vitest, а для поведения компонентов - React Testing Library. Называйте тесты `*.test.ts` или `*.test.tsx` и размещайте их в `__tests__` или рядом с проверяемым модулем. Новое поведение музыкальной теории покрывайте в `src/music/__tests__`; интерактивный UI проверяйте через доступные role/text assertions. Перед отправкой изменений запускайте `npm run test`, `npm run lint` и `npm run typecheck`.
